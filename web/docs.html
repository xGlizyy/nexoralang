    Getting to know NEXORA

    A short, honest overview of the project: what it is, what exists today and where it is going.

    NEXORA is in early development. A first interpreter runs a small subset of the language; the rest of this page describes a design in progress, and the syntax may change as the language evolves.

    What is NEXORA

    NEXORA is a new programming language being built from scratch as an independent project. Its aim is to explore a clearer, more expressive way to write software: a syntax of its own, modern development tools and, over time, carefully chosen AI-related features.

    It is not a framework or a layer on top of another language. It is a language design that will get its own implementation, tooling and documentation, step by step.

    Current status

    The project is at an early stage. This is what exists today and what does not:

    Available
    • A reference interpreter, version 0.6, that runs a subset of the language from the command line.
    • Rules written in the code and checked by the interpreter: contracts (requires, ensures) and refined types (type Percent = Int where ...), loops that declare why they end (decreases) and what they keep (invariant), each with an optional explanation, and examples in functions (example) checked with nex test.
    • Operations on text (Text.length, Text.slice, ordering) and reading numbers with Int.parse and Float.parse, each function stating the requirements it checks.
    • A language specification for that subset, and a broader design draft.
    • A playground that runs code in the browser with that interpreter, and a short language guide.
    • This website and this first documentation page.
    Experimental
    • The syntax itself. It is still being defined and can change.
    • Most code examples on this site. Unless stated otherwise they are illustrations, not runnable programs.
    Planned
    • The rest of the language: collections and for, reading input, modules.
    • More developer tools.
    • Optional AI integrations, currently at the research stage.

    The full design draft is available as a working document: Language design draft v0.1 (written in Spanish). It is more detailed than this page and some of its notation differs from the examples shown here.

    Design philosophy

    Three goals guide the decisions made so far. They are intentions, not finished features.

    Clarity first

    Code is read far more often than it is written. NEXORA aims for a syntax that is readable, consistent and easy to understand, with few special cases to remember.

    Built to evolve

    The language is designed so that tools, documentation and an ecosystem can grow around it without having to rethink its foundations.

    AI, thoughtfully integrated

    The project is exploring how AI tools could fit into the language. The intent is for them to stay optional: writing NEXORA should never require an AI service, and nothing is promised before it exists.

    Ideas the current draft is exploring:

    • Values that are immutable unless declared otherwise.
    • Errors handled as ordinary values rather than exceptions.
    • Function signatures that state their types explicitly.

      Frequently asked questions

      Short answers to the questions that come up most often about the project and how to take part in it.

      About the project

      Is NEXORA ready for production?

      Not yet. Version 0.6 is an experimental development release. It can be explored and tested, but production suitability has not been established.

      Is NEXORA a replacement for Python?

      No such claim is made. The current implementation uses Python, and the project explores its own language design goals.

      It should be evaluated on its actual capabilities rather than as a general replacement for Python or another established language.

      Can I use NEXORA to learn about programming languages?

      Yes. Exploring the available syntax, examples, interpreter behavior, diagnostics and design records can be useful for learning and experimentation. The playground and the language guide are good places to start.

      Getting involved

      Can I contribute?

      You can provide feedback and explore potential contributions. Check the project's public repository and contribution instructions, if available, for the current process.

      Where should I report a bug?

      Use the project's official issue tracker if one is published. Include:

      • The NEXORA version (nex --version);
      • The operating system;
      • The smallest program that reproduces the issue;
      • The command you ran;
      • The actual output.
      What should I do if a feature is missing?

      Check the language documentation and limitations first. If the feature is not supported, treat it as a possible future proposal rather than assuming the language is behaving incorrectly.
