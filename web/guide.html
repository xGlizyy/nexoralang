    Language guide

    NEXORA, as it works today

    A short tour of what the current interpreter (version 0.8) accepts. Every program on this page is run by the project's tests, and every one can be tried in the playground.

    NEXORA is in early development. The syntax may change, and the language is still small: the limitations are listed at the end.

    Introduction

    A program is one .nex file. It starts running at the function main. print writes a value followed by a line break.

    Before running anything, NEXORA checks the whole program: names, types and whether every function returns what it promises. A program with an error is never started.

    Syntax

    • A statement ends at the end of its line. There are no semicolons.
    • Blocks are written with braces. Indentation is free.
    • A comment starts with // and runs to the end of the line.
    • let declares a variable. Variables never change: there is no reassignment.
    • A name can only be declared once while it is visible. There is no shadowing.
    • Text is written between double quotes, on one line.

    Types

    TypeValuesWritten as
    IntWhole numbers, 64 bits42, 1_000_000
    FloatNumbers with decimals3.14, 10.0
    BoolTrue or falsetrue, false
    TextText"Hello"
    List[T]An immutable list of values of type T[1, 2, 3]
    A recordA type the program declares, with immutable fieldsPoint(x: 1, y: 2)
    VoidNo value: only as a return type

    The type of a variable is inferred from its value, or written after a colon. All types are known before the program runs, so a type error can never appear while it is running.

    Nothing is converted implicitly. An Int and a Float are never mixed, and a number is never joined to a text. Conversions are explicit calls: to_float, to_int and to_text.

    Operators

    OperatorsWork onResult
    + - * /Two Int or two FloatThe same type
    +Two TextText
    == !=Two values of the same typeBool
    < <= > >=Two Int or two FloatBool
    and or notBoolBool

    Multiplication and division come before addition and subtraction, then comparisons, then and, then or. Dividing two Int gives an Int: the fractional part is dropped. Comparisons cannot be chained.

    Functions

    Every parameter states its type, and the return type is always written. A function that returns a value must end with return on every path. if and else choose between blocks; the condition must be a Bool. A function may call itself; to repeat something many times, a loop needs no stack.

    Contracts

    A function can state what it expects from its caller (requires) and what it promises (ensures, where result is the value returned). The clauses go at the start of the body. They are checked while the program runs, on every call: they are not proven in advance.

    After a comma, a rule can carry its explanation. It does not change what is checked: when the rule is broken, the error shows it as the reason, so whoever broke it does not have to guess why it exists.

    Refined types

    A refined type is a built-in type plus a rule that all its values follow. Every value of the type satisfies the rule, everywhere in the program. A value can only get the type in two ways, and both are written in the code:

    • A constant, such as 15 below: it is checked before the program runs.
    • An explicit check, such as Cents(...): it happens while running, and stops the program if the value breaks the rule.

    A Percent can be used wherever an Int is expected, but not the other way round. Arithmetic on refined values gives the base type. A constant that breaks the rule is found without running:

    Loops

    A variable that has to change is declared with var; let never changes, and neither do parameters. A while loop repeats its body while its condition is true, and says at the start of its body why it is correct:

    • decreases: a whole number that never goes below 0 and gets smaller on every turn. It is the reason the loop ends. Every loop has exactly one.
    • invariant: a condition that holds before every check of the loop condition. As many as needed.

    Both are checked on every turn while the program runs. A loop never hangs: it ends, or it stops on the turn where its measure did not get smaller, and the error says which turn and which values the variables had. A loop without a measure is found before running:

    Lists

    A list is written between brackets, and all its elements have the same type: List[Int], List[Text], or even List[List[Int]]. A list never changes. List.append and List.concat build a new list and leave the old one as it was. List.length, List.get and List.contains read it.

    A for loop walks a list, one element per turn. It can declare invariants like a while, but it needs no decreases: it ends when the list does.

    List.get declares which indexes it accepts, from 0 to the length minus one: any other index stops the program and says which rule was broken. An empty list says nothing about the type of its elements, so it needs one written:

    Records

    A record is a type the program declares, with fields that never change: type Point = { x: Int, y: Int }. It is built by giving every field a value, by name: Point(x: 1, y: 2). The order of the fields does not matter, but each one is given once and all of them are required.

    A field is read with a dot, p.x, and the fields can be chained: segment.to.x. A record never changes, so there is no way to assign to one of its fields.

    Two records are different types even when they have the same fields: the identity of a record is the identity of its declaration. Two values of the same record are compared by value, field by field.

    Texts

    Some functions belong to a type and are called with its name: Text.length, Text.slice, Text.contains, Text.starts_with, Text.ends_with, and Int.parse and Float.parse to read a number written in a text. A character is a Unicode code point, and texts are ordered by code point with <, the same on any machine: "Z" < "a" is true.

    The functions that may have no answer say when they have one, with a requires written in NEXORA. Text.slice("abc", 2, 9) does not quietly return "c", and Int.parse("12a") does not return 12: both stop the program and explain which rule was broken. Check first with Int.can_parse:

    Diagnostics

    When something is wrong, NEXORA says what kind of problem it is, where it is, and what was expected. Each problem has a stable code. This program has a type error, found without running it:

    KindMeaningFound
    lexicalA character that is not part of the languageBefore running
    syntaxThe code does not follow the grammarBefore running
    semanticNames, scopes, return pathsBefore running
    typeTypes that do not matchBefore running
    runtimeDivision by zero, overflow, endless recursionWhile running
    contractA rule the program declares was broken: a requires or ensures condition, the rule of a refined type, a loop invariant or a loop measureWhile running

    In the playground, selecting a diagnostic shows its position in the editor.

    Limitations

    These do not exist yet. Using them is an error, not something the playground pretends to support:

    • break and continue, and for over anything that is not a list, such as a range of numbers or a text.
    • Writing xs[i], changing an element, or map, filter and sorting on lists.
    • Any other compound type besides lists and records: no maps, no enums, no Option.
    • Operations on text beyond the ones in Texts: no trim, upper case, split or replace.
    • Reading input, files or the network: a program can only print.
    • Modules: a program is a single file.
    • Any integration with AI models.

    Limits of the implementation:

    • At most 1000 nested calls.
    • Int is a 64-bit integer; going out of range stops the program.
    • In the playground, a program is stopped after a time limit and if it prints too much.

    The interpreter is a reference implementation: it has not been measured for speed, and NEXORA is not ready for production use.
